Chaite 插件开发手册

为 Sy-Bot / Chaite 智能体打造的轻量化、高扩展插件标准。无论是单文件 JS 极速热重载，还是目录工程模块，都能轻松编写。

1. 设计理念与解耦

痛点告别： 旧式 Bot 框架往往要求插件直接面向底层协议实现（如面对复杂的 icqq 嵌套段落、CQ 码拆包），只要更换底层实现（如转向 OneBot v11、SnowLuma 或飞书），所有插件就会崩溃。

Chaite 彻底移除了原先简陋的旧触发器（Triggers），构建了统一事件对象 ChaiteEvent。插件只关心通用的逻辑：监听指令、收发消息、调用模型、持久化存储。底层适配器保证事件的无缝对齐。

2. 两种插件规格

单文件 Single-File JS

  • 路径：runner/plugins/<name>.js
  • 无需构建，即存即用
  • 支持 Web 后台在线编辑并即时热重载
  • 适合：小游戏、趣味互动、单指令工具

工程包 Directory Package

  • 路径：runner/plugins/<name>/
  • 含 package.json 与入口 index.js
  • 自带 config.json，配置随插件走，方便拷贝分享
  • 适合：多文件业务、企业接口、复杂集成

3. 快速起步：最小实例

创建一个文件 runner/plugins/hello.js 即可自动加载运行：

// runner/plugins/hello.js
export const name = '打招呼插件'
export const version = '1.0.0'

export default function setup(ctx) {
  ctx.logger.info('问候插件启动成功！')

  // 注册指令：#打招呼
  ctx.registerCommand('#打招呼', async (e) => {
    await e.reply(`你好呀，${e.sender.nickname || e.userId}！`)
    return true // 返回 true 表示拦截并完成处理
  })
}

4. 统一事件对象 (ChaiteEvent) API 规范

所有消息事件均封装为标准 ChaiteEvent 对象传递给插件：

字段 / 方法 类型 说明
e.userId string | number 发送者用户 ID（私聊或群成员唯一标识）
e.groupId number | null 群号（私聊时为 null）
e.isGroup / e.isPrivate boolean 当前是否为群聊 / 私聊环境
e.text string 清洗后的文本（已剥离 @ 机器人与指令前缀）
e.rawText string 未经清洗的原始消息文本
e.sender SenderInfo 发送者信息：{ nickname, card, role, title, level }
e.images ImageAttachment[] 携带的图片数组 [{ ref, url, mimeType }]
await e.reply(content) Promise<any> 统一回复方法，支持字符串或对象，底层自动转换为对应协议段
await e.queryAI(prompt, [opt]) Promise<string> 直接调用系统配置的主模型/预设提问（单轮直通）
await e.askWithContext(prompt, [opt]) Promise<string> 携带群聊近期双水位线滑动窗口记录向模型提问

5. AI 能力赋能

你不需要在插件里手动引入 OpenAI SDK 或拼接请求头，Chaite 为插件提供开箱即用的大模型调用接口：

ctx.registerCommand('#今日诗词', async (e) => {
  // 1. 单轮直调 AI
  const poem = await e.queryAI('请以"春雨"为题写一首七言绝句，直接输出诗文')
  await e.reply(poem)
  return true
})

ctx.registerCommand('#总结讨论', async (e) => {
  if (!e.isGroup) {
    await e.reply('请在群聊中使用总结功能哦')
    return true
  }
  await e.reply('正在阅读刚才的群消息，请稍候...')
  // 2. 携带当前群聊上下文
  const summary = await e.askWithContext('请用活泼的语气总结刚才群友的核心讨论，列出3个看点')
  await e.reply(summary)
  return true
})

6. 轻量持久化 KV 存储

每个插件都自动注入了一个完全数据隔离的 ctx.storage 客户端（基于主数据库 SQLite），无需自行管理连接或文件并发：

// 存储数据（支持基础类型与任意 JSON 对象）
await ctx.storage.set('user_level_' + e.userId, 5)

// 获取数据（支持设置默认回退值）
const level = await ctx.storage.get('user_level_' + e.userId, 1)

// 删除数据
await ctx.storage.delete('user_level_' + e.userId)

// 静态配置（直接读取随插件自带的 config.json）
const customPrefix = ctx.config.myPrefix || '#默认'

7. 工具注入 (Function Calling) 与定时任务

通过向全局大模型注册 Tool，可以让预设在思考时自主调用插件中的功能：

export default function setup(ctx) {
  // 1. 注册 Function Calling 工具
  ctx.registerTool({
    name: 'query_inventory',
    description: '查询某样物品的当前库存数量',
    parameters: {
      type: 'object',
      properties: {
        itemName: { type: 'string', description: '物品名称' }
      },
      required: ['itemName']
    }
  }, async (args) => {
    return { stock: 42, item: args.itemName }
  })

  // 2. 注册定时任务（重载或禁用插件时系统会自动安全清理，防止泄漏）
  ctx.cron('0 8 * * *', async () => {
    ctx.logger.info('早上 8 点整定时播报触发！')
  })
}
